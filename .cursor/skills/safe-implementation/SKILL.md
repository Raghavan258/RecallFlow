# Safe Implementation
1. Confirm desired behavior and acceptance criteria.
2. Inspect relevant code and conventions.
3. Prepare a plan for multi-file or nontrivial changes.
4. Identify affected APIs, dependencies, and regression risks.
5. Implement the smallest complete solution.
6. Preserve unrelated user changes.
7. Run focused checks and inspect the final diff.
8. Report changed files, actual results, and remaining risks.
Ask before destructive actions, deployments, or significant architectural changes.\n
